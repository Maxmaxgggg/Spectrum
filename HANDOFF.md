# Передача: что сделано и что дальше

Состояние на 3 октября 2026 года, ветка `claude/quirky-rubin-51corb`: 25
коммитов поверх `main`, `main` целиком входит в ветку. Следующая цель —
перенести достижения на видеокарту: всё, что сейчас считается только на
процессоре или на видеокарте ни разу не запускалось.

## Задача программы

Весовой спектр двоичного линейного кода по порождающей матрице. Нужен низ
спектра — первые компоненты, по ним строится характеристика кода. Qt 5,
C++14, MSVC и CUDA 12 на Windows, GMP для больших чисел. Сборка —
`Spectrum.vcxproj` (приложение) и `tests/SpectrumTests.vcxproj` (тесты).

Алгоритмы:

- **Код Грея** — полный перебор 2^k, до 63 строк. CPU и GPU.
- **Дуальный код** — полный перебор проверочной матрицы (n − k строк) и
  преобразование Мак-Вильямс (`compute/dualcode.cpp`, GMP). CPU и GPU.
- **Брауэр–Циммерман** (БЦ) — низ спектра с гарантией: перебор до r строк
  на нескольких информационных множествах, слово засчитывает одно множество
  (`bzKeep`). CPU и GPU, короткий путь (k ≤ 63) и длинный.
- **Стохастический поиск** (Леон, Ли–Брикелл, окно Штерна–Дюмера) — низ
  спектра с заданной вероятностью пропуска, оценка ненайденного по Чао.
  CPU и GPU (`compute/leonkernel.cu`).
- **Код-произведение** — низ спектра C1 ⊗ C2 по компонентам, по рангам
  слов, точно до границы Толхёйзена и выше (`compute/product.h`). Верхний
  уровень — только CPU; компоненты считает вложенный Worker, он может идти
  на GPU.

Структура кода выбирается в настройках: «Нет», «Код-произведение», «БЧХ»
(`ComputationSettings::cyclic`).

## Что сделано (по коммитам)

### Ошибки
- `abc8af8` — отмена посреди чанка на CPU портила чекпоинт.
- `e3331f0` — счётчики в JSON автосохранения теряли точность после 2^53
  (теперь строкой, `JsonU64`).
- `5d3de0c` — самописное копирование `ComputationSettings` теряло матрицы.

### Рефакторинг
- `6ab7cab`, `cf0da4d` — общие для хоста и ядер примитивы: `bitops.h`,
  `mixing.h`, `wordvariants.h` (диспетчер по числу 64-битных слов
  `dispatchWords`), `combinations.h` (ранг/сочетание, Госпер). Помечены
  `SPECTRUM_HD`.
- `d3fefae` — Мак-Вильямс одной реализацией (рекуррентность Кравчука).
- `edc18f0` — общий цикл по чанкам `Worker::runChunks` вместо шести копий;
  пути расчёта разнесены: `worker_cpu.cpp`, `worker_gpu.cpp`,
  `worker_leon.cpp`, `worker_product.cpp`.
- `3153ab7`, `da51e1b`, `5a220f8`, `d9e5111` — спектр числами
  (`SpectrumCounts`), настройки структурой, интерфейс без заголовков CUDA,
  уборка.
- `2148fea` … `3fff79f` — единые имена; правила в `NAMING.md`, проверка —
  `.clang-tidy` (`tools/linux-check/tidy.sh`).

### Алгоритмы
- `c7a385d` — **БЦ, неполный последний слой**: последний слой идёт только по
  тем множествам, что нужны для гарантии (`InfoSets::Depth{maxRows,
  lastLayerSets}`, `infosets.h`). Проверено: 80 прогонов с неполным слоем
  против полного перебора, обрыв и досчёт посреди неполного слоя.
- `70f4aa9`, `0e195d6` — **стохастический поиск по орбитам сдвигов** у
  циклических кодов (`cyclic.h`): ловить достаточно любое слово орбиты,
  таблица хранит представителя орбиты. Нижняя граница вероятности поимки
  орбиты — по Чжуну–Эрдёшу с вогнутой оболочкой совместных вероятностей
  (`Leon::orbitCatchProbability`). Работы меньше в 4–23 раза (БЧХ [63,45] до
  веса 11 — в 13 раз, Хэмминг [63,57] до 5 — в 23). Орбита ловится в 9–26
  раз вероятнее слова на кодах длиной до 1023.
- `29893f7` — **БЦ по сдвигам одного множества** (подход Чена) у циклических
  кодов: перебор первых k столбцов круга до r строк гарантирует все слова
  веса < ⌈L(r+1)/k⌉; орбита засчитывается одним словом со своим размером
  (правило — `compute/cyclicorbit.h`, общее для хоста и ядер). Комбинаций
  меньше, чем по нескольким множествам: БЧХ [63,45] до веса 10 — в 79 раз,
  [63,36] до 12 — в 325, [127,113] до 5 — в 22. Ядра `xorKernelShort` и
  `xorKernelLong` получили параметр `bool CYCLIC`; машинный код прежних 51
  варианта не изменился побайтно. Запись автосохранения — версии 2,
  продолжается только на той же глубине.
- `6c10827` — **«Структура кода» в настройках**: «БЧХ» включает сдвиги явно;
  матрица без циклического сдвига — ошибка, а не тихий обычный перебор.
- `fee89ed` — **код-произведение одной матрицей**: в поле — матрица самого
  произведения G1 ⊗ G2 (кронекерово, порядок любой), компоненты находит
  `Product::factor`. Вторая вкладка матрицы убрана; старые настройки и
  записи переводятся.

Литература, на которую опирались: Брауэр–Циммерман и реализации Algorithm
994/1033 (Hernando и др.), Bouyuklieva 2021, Lisoněk–Trummer 2016
(разбиение матроида на множества), Леон / Штерн–Дюмер / оценка Чао, Чен —
БЦ для циклических кодов, Толхёйзен и El-Khamy–Garello — спектр
произведения.

## Видеокарта: что где и что не проверено

| Путь | CPU | GPU |
|---|---|---|
| Код Грея, дуальный | да | `grayKernel` |
| БЦ, несколько множеств | да | `xorKernelShort/Long<W,false>`, `bzKeep` |
| БЦ, неполный последний слой | да | те же ядра, срезы по множествам |
| БЦ по сдвигам | да | `xorKernelShort/Long<W,true>`, `countOrbit` — проверено только ptxas |
| Леон | да | `leonTrialsKernel` |
| Леон по орбитам | да | ядро ищет слова, к орбитам приводит хост |
| Окно Штерна–Дюмера | да (по умолчанию) | есть, выключено (`WindowPolicy::gpu = false`) |
| Код-произведение, верхний уровень | да | нет (`g.useGpu = false`) |
| Полный перебор компоненты (`Product::bruteForce`) | да | нет |
| Свёртка рангов (`Product::profiles`, `rankR`) | да (OpenMP) | нет |

Ни одно изменение этой ветки на видеокарте не запускалось: в облачном
контейнере её нет, ядра здесь только компилируются до машинного кода.
Из 296 тестов 174 GPU-случая здесь пропускаются. Их надо прогнать на машине
пользователя первым делом:
`tests\x64\Release\SpectrumTests.exe`, последняя строка — `итого: пройдено
…, провалено …`.

## План переноса на видеокарту

По порядку; у каждого пункта — где смотреть и как проверить.

1. **Прогнать GPU-тесты** и починить провалы. Правило тестов: GPU обязан
   совпасть с CPU слово в слово (`expectSame`) и с точным спектром
   (`checkBzExact`). Ни один GPU-тест не пропускать и не ослаблять.

2. **БЦ по сдвигам на GPU — давление на регистры.** Проверка орбиты
   (`CyclicOrbit::designatedOrbit`, `__noinline__`) подняла регистры:
   `xorKernelShort<1,true>` — 55 против 28, `<4,true>` — 56 против 40
   (`ptxas -v`). Лёгких слов единицы на миллионы, поэтому вариант: ядро
   только складывает лёгкие слова в буфер, а орбиты считает второе ядро или
   хост. Мерить на реальной карте: `--bz-run bch:6,3 10 gpu-bch` против
   `gpu` (суффикс `-bch` — структура «БЧХ»).

3. **Орбиты Леона — на устройство.** Сейчас ядро отдаёт каждое найденное
   слово, а хост приводит его к представителю (`Cyclic::canonical`, O(w·L) на
   слово) и считает поимки. Функции `cyclicorbit.h` уже собираются под
   устройство: можно приводить к представителю в ядре и держать в таблице
   видеокарты (`Seen` в `worker_leon.cpp`) орбиты, а не слова. Тогда и
   поимки для оценки Чао считаются на устройстве (сейчас при симметрии это
   отключено: `hostCountsHits`).

4. **Окно Штерна–Дюмера на GPU**: ядро умеет, но цена попытки не
   откалибрована (`Leon::plan`, `costPerTrial`). Замерить и включить там, где
   выгодно.

5. **Код-произведение на GPU.**
   - Полный перебор компоненты со списком слов (`Product::bruteForce`, k ≤ 28)
     — ядро Грея плюс выгрузка слов до веса.
   - Свёртка рангов r ≥ 2: `Product::profiles` (перебор независимых наборов
     лёгких слов с отсечкой по объединению носителей) и `Product::rankR` —
     сейчас OpenMP, потолок работы `WORK_LIMIT` в `worker_product.cpp`.
   - Ранг 1 — свёртка спектров, мгновенная, переносить незачем.

6. **Сложения в ядрах БЦ (Algorithm 994).** Сейчас шаг перебора — Госпер по
   развёрнутой маске с XOR изменившихся строк. В Algorithm 994 — порядок
   «вращающейся двери» (ровно две строки на шаг) и сохранённые частичные
   суммы первых строк. Мерить только на карте.

7. **Предел константной памяти.** Матрицы всех множеств БЦ должны
   поместиться в 64 КБ (`Constants::MAX_CONST_WORDS`, `MAX_INFO_SETS` = 16),
   и это ограничивает число множеств у больших k. Вариант — множества в
   глобальной памяти, как у длинного пути.

## Как проверять

- **Windows (машина пользователя):** собрать Release, прогнать
  `SpectrumTests.exe`; отдельные расчёты — `--bz-run`, `--leon-run`,
  `--dual-run`, `--product-run` (описание — `tests/README.md`).
- **Облачный контейнер (нет MSVC и GPU):** `tools/linux-check` — g++ для
  `.cpp`, clang для `.cu` (устройство — PTX и ptxas sm_86), окно без экрана.
  `setup.sh`, потом `check.sh [база]`; `compare.sh база` показывает, какие
  ядра изменились по машинному коду и совпал ли эталонный дамп. Запустить
  ядро здесь нельзя: правка ядра проверяется только на карте пользователя.
