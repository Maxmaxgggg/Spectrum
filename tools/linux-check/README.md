# Проверочная сборка под Linux

Для облачного контейнера, где нет ни MSVC, ни видеокарты. Собирает тесты и
приложение тем же набором файлов, что и проекты Visual Studio (списки
берутся из `.vcxproj`), гоняет тесты на CPU, открывает окно без экрана и
сравнивает машинный код ядер с базовым коммитом. Репозиторий не трогает:
всё собирается из копии в `$WORK` (по умолчанию `/tmp/spectrum-check`).

Отличия от Windows сведены к двум заголовкам: `compat.h` (интринсики MSVC
через встроенные GCC) и `compat_cu.h` (атомарные операции для `unsigned
long`, `__ldcg` для clang 18). Ещё в копии `uint64_t` заменяется на
`unsigned long long`: на Linux это разные типы, на Windows — один.

| Скрипт | Что делает |
|---|---|
| `setup.sh` | Qt 5, GMP, clang, clang-tidy из apt; ptxas и libcudart из колёс pip NVIDIA в `$CUDA_ROOT` (`/tmp/cuda`); один раз, несколько минут |
| `build-tests.sh [каталог]` | `SpectrumTests`; ядра — в PTX и через ptxas sm_86 в cubin |
| `build-app.sh [каталог]` | приложение (qcustomplot собирается один раз и переиспользуется) |
| `gui-smoke.sh` | окно без экрана: расчёт кнопкой, «БЧХ» из диалога, код-произведение, перенос старых настроек |
| `tidy.sh` | имена по `.clang-tidy`; печатает предупреждения |
| `compare.sh база` | ядра по функциям cubin против коммита `база`: совпало, тот же код под новым именем, отличается, пропало, новое; и эталонный дамп спектров |
| `check.sh [база]` | всё по порядку; журналы — в `$WORK/logs`. На 4 ядрах с базой — около 8 минут |

Один тест: `ONLY=testBzCyclic /tmp/spectrum-check/tests/SpectrumTests` —
разбор `ONLY` вставляется только в копию.

GPU-тесты без видеокарты пропускаются сами (`ПРОПУСК … (GPU недоступен)`).
Правку ядра здесь можно проверить только на то, что она собирается, что
ptxas её принимает (`ptxas -v` покажет регистры и стек) и что соседние ядра
не изменились (`compare.sh`). Верна ли она — покажет только прогон на
карте.
